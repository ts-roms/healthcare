# Compliance dependencies register

The platform records data and enforces workflow rules; it does **not** claim regulatory compliance and encodes no
regulatory rule for which official requirements have not been obtained (root `CLAUDE.md` §36). This page collects the
open items in one place. Each row names what the platform does today, what it deliberately does not encode, and who
must validate it before production certification. The domain documents linked below hold the detail.

Integration dependencies (PhilHealth, DOH case reporting, payment provider) are tracked separately in
[`docs/interoperability/dependencies.md`](../interoperability/dependencies.md).

## Rules for changing this page

- Add a row when a feature stops short of a regulatory rule; link the domain document that explains it.
- Remove or change a row only when the requirement has been validated against the current official source, and record
  that source and date in the domain document. Never encode a rule from memory.
- Do not describe a feature as compliant merely because it exists.
