# Release v1.1.0 (draft)

**Status:** draft, on the local branch `release/v1.1.0`, not pushed, not tagged. Not tested on real kiosk, printer or display hardware. Fill in the
"How it was tested" table from the final runs before tagging.

A minor release: it adds behaviour, and carries the security audit's fixes (some change what staff see: see "Changes you may notice").

## Highlights

- **Patient self-service kiosk** (off until set up). A touch-screen kiosk where patients identify themselves, check in for an appointment or as a walk-in and
  take a queue number; new patients register for reception to review. Ticket printing through a local **print agent**, a waiting-room screen that calls
  numbers (optional chime and voice, one at a time), reception screens for registrations, recall, no-show and put back in line. See
  [the kiosk domain note](../domains/kiosk.md) and the Help manual (Appointments and queue → How to set up a patient kiosk).
- **Calendar Day view** redesigned: the hours of the day with overlapping entries side by side, day figures, what is next, and the selected entry in full.
- **MyHealth home** tells patients about the kiosk while one is in service; the public **`/welcome`** page has a Kiosk section.
- **Visit types** have a **Patient kiosk** option; the **Devices** screen manages kiosks, screens and print agents.
- **Help manual:** a guide to setting up a facility by type, a kiosk set-up guide, and 24 permissions and two roles that were missing from the tables.
- **Security audit fixes** (batches in `docs/security-audit/REMEDIATION_CHANGELOG.md`) and the kiosk audit
  ([final report](../security/kiosk-audit-final-report.md)): 15 findings, none Critical or High; twelve fixed pending verification (one is documentation only), one accepted risk, one partly addressed and one open.

## Before you deploy

1. **Migrations `0136` to `0143`** run in the API's pre-deploy step (`pnpm db:migrate`); they are forward-only and additive:

   | Migration | What it adds                                                                                                    |
   | --------- | --------------------------------------------------------------------------------------------------------------- |
   | `0136`    | Permission `patient.identifier.reveal` (government and insurance identifiers shown unmasked)                    |
   | `0137`    | Kiosk tables, role **Patient kiosk**, `kiosk.*` permissions, `visit_type.kiosk_enabled`, `visit.checked_in_via` |
   | `0138`    | Queue actions: recall, no-show, put back in line                                                                |
   | `0139`    | Ticket print jobs, device kinds (kiosk / display), display settings, role **Kiosk print agent**                 |
   | `0140`    | `kiosk_device.prints_tickets` (off by default)                                                                  |
   | `0141`    | Reviewer claim on kiosk registrations                                                                           |
   | `0142`    | `kiosk_device.print_agent_user_id`                                                                              |
   | `0143`    | Printer settings per kiosk: `printer_connection`, `printer_host`, `printer_port`, `paper_mm`                    |

2. **Deploy order:** `api` first (it migrates), then the workers, then `staff` and `portal`, then the new **`kiosk`** app.
3. **The kiosk app is a new service** (`apps/kiosk`, its own `railway.json`, port from `PORT`), declared in `infrastructure/terraform/railway/` (`kiosk`; a public
   domain, `API_BASE_URL`, and `kiosk_privacy_notice` for `KIOSK_PRIVACY_NOTICE`). Run `terraform plan` and review the new service and domain before applying. Without
   Terraform, create the service by hand with `API_BASE_URL` (the API address including `/api/v1`) and optionally `KIOSK_PRIVACY_NOTICE` and `KIOSK_APP_VERSION`.
4. **The print agent** (`tools/kiosk-print-agent`) is not deployed with the platform; its printer is set in the staff app (**Queue → Devices → Edit → Printer**), so its
   environment holds only the API address and its sign-in (and a printer connected to its own computer, if any). `FACILITY_ID`, `DEVICE_CODES` and `PRINTER_*` are
   optional, and `PAPER_MM` is gone (the paper width is a setting). It is not deployed with the platform: it runs on a machine next to a printer, only for clinics that print
   tickets. It runs from the repository (`pnpm kiosk:print-agent`); a packaged install is not built. Follow `docs/runbooks/kiosk-print-agent.md`.
5. **Production configuration checks:** the API now refuses the placeholder JWT secret and the sample MFA key in production (security audit VR-21).
   Check both are set to real values before the first start.

Nothing kiosk-related appears until an administrator ticks **Patient kiosk** on a visit type, creates a kiosk account and registers the device. **Prints
tickets** is off for every new kiosk.

## Changes you may notice

- **Government and insurance identifiers are masked** (last four digits) in the patient record and merge preview unless the person holds
  `patient.identifier.reveal`. Organization administrators, records officers, receptionists and cashiers keep seeing them in full; clinical roles see the masked form.
- **Managing users:** suspending, resetting or revoking a member needs every permission that member holds; a facility-scoped user manager can grant only at
  their own facilities and not to themselves.
- **Uploads:** the bytes of an uploaded file must match its declared type.
- **Rate limits:** kiosk, print agent and waiting-room screen routes are counted per signed-in device account; while Redis is unreachable the limiter counts
  in memory instead of letting everything through.
- **Web apps** send browser security headers; the kiosk app also sends a per-request script policy.
- The visit types screen has a **Patient kiosk** column, and the Devices screen a **Print agent** choice per kiosk.

## Rollback

Migrations are forward-only. The new tables and columns are additive and older code ignores them, so redeploying the previous version works without undoing a
migration. Do not drop the new tables. See `docs/runbooks/releases.md`.

## Known gaps

- **Intermittent printing journey.** In two earlier full runs the first test of the printing journey failed because the print agent was still waiting out a refused
  sign-in when the test checked in a ticket (the API accepts about ten sign-ins a minute per address). The journey now waits for the agent to sign in; the next full run
  passed, which is not proof that it cannot recur.

- Kiosk audit finding **KA-10** (guidance, now in the manual) is closed as documentation; **KA-11** (no browser journey yet for the voice announcement, queue
  transfer from a kiosk ticket or several browsers at once) and **KA-12** (hardware and ZAP checks not run) are open; twelve findings are _fixed, pending
  verification_, not verified.
- A print agent that crashes between printing and reporting can print one ticket twice; a very slow print could be repeated by a second agent; tickets are plain
  ASCII; the Devices page does not refresh by itself; the kiosk screen has no Filipino wording.
- Compliance items stay with the organization: the kiosk's privacy notice wording, how long kiosk sessions and print history are kept, what a kiosk may
  collect. See `docs/security/compliance-dependencies.md`.
