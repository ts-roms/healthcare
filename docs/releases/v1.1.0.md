# Release v1.1.0 (draft)

**Status:** draft, on the local branch `release/v1.1.0`, not pushed, not tagged. Not tested on real kiosk, printer or display hardware. Fill in the
"How it was tested" table from the final runs before tagging.

A minor release: it adds behaviour, and carries the security audit's fixes (some change what staff see: see "Changes you may notice").

## Highlights

- **Patient self-service kiosk** (off until set up). A touch-screen kiosk where patients identify themselves, check in for an appointment or as a walk-in and
  take a queue number; new patients register for reception to review. Ticket printing through a local **print agent**, a waiting-room screen that calls
  numbers (optional chime and voice, one at a time), reception screens for registrations, recall, no-show and put back in line. See
  [the kiosk domain note](../domains/kiosk.md) and the Help manual (Appointments and queue → How to set up a patient kiosk).
- **Calendar Day view** redesigned: the hours of the day with overlapping entries side by side, day figures, what is next, and the selected entry in full.
- **MyHealth home** tells patients about the kiosk while one is in service; the public **`/welcome`** page has a Kiosk section.
- **Visit types** have a **Patient kiosk** option; the **Devices** screen manages kiosks, screens and print agents.
- **Help manual:** a guide to setting up a facility by type, a kiosk set-up guide, and 24 permissions and two roles that were missing from the tables.
- **Zero-trust audit and fixes** ([report](../security/zero-trust-audit-2026-11-06.md)): every high finding and most medium ones fixed — least-privilege
  database role enforced, audit removal held by an owner-only floor, the instrument gateway on its own role and analyzer allowlist, facility checks on invoices
  and lab orders, documents gated by category, patient data no longer left in the offline cache, platform administrators on two-step verification, live
  updates re-checked every minute, public routes scoped to their organization, single-use sign-in challenges and tickets. Several change deployment: read
  "Before you deploy" step 6.
- **Security audit fixes** (batches in `docs/security-audit/REMEDIATION_CHANGELOG.md`) and the kiosk audit
  ([final report](../security/kiosk-audit-final-report.md)): 15 findings, none Critical or High; twelve fixed pending verification (one is documentation only), one accepted risk, one partly addressed and one open.

- **Pre-registration from MyHealth** (off until an organization turns it on with its own privacy notice): people who are not yet
  patients send their details before a first visit; reception reviews them with the kiosk's requests; nothing becomes a patient
  or access until approved. See the kiosk domain note.

## Before you deploy

1. **Migrations `0136` to `0150`** run in the new one-off `migrate` service (`pnpm db:migrate`, ADR-0016); they are forward-only and additive:

   | Migration | What it adds                                                                                                                                                                              |
   | --------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
   | `0136`    | Permission `patient.identifier.reveal` (government and insurance identifiers shown unmasked)                                                                                              |
   | `0137`    | Kiosk tables, role **Patient kiosk**, `kiosk.*` permissions, `visit_type.kiosk_enabled`, `visit.checked_in_via`                                                                           |
   | `0138`    | Queue actions: recall, no-show, put back in line                                                                                                                                          |
   | `0139`    | Ticket print jobs, device kinds (kiosk / display), display settings, role **Kiosk print agent**                                                                                           |
   | `0140`    | `kiosk_device.prints_tickets` (off by default)                                                                                                                                            |
   | `0141`    | Reviewer claim on kiosk registrations                                                                                                                                                     |
   | `0142`    | `kiosk_device.print_agent_user_id`                                                                                                                                                        |
   | `0143`    | Printer settings per kiosk: `printer_connection`, `printer_host`, `printer_port`, `paper_mm`                                                                                              |
   | `0144`    | Owner-only `audit_retention_floor`; audit archives start pending; owner maintenance functions not run by the app                                                                          |
   | `0145`    | Role **Instrument gateway** (`lab.instrument.message.submit` only); the permission removed from org_admin                                                                                 |
   | `0146`    | The application role holds nothing on the audit trail's partitions (read through `audit_event` only)                                                                                      |
   | `0147`    | `consumed_token`: sign-in challenges and live-update tickets are spent once                                                                                                               |
   | `0148`    | `kiosk_device.allowed_networks`: optional addresses or ranges a kiosk may be used from (empty = anywhere)                                                                                 |
   | `0149`    | `organization_id` on care-plan goals, problems and notes, prescription lines and notification attempts (row-level security); idempotency records per organization (existing ones deleted) |
   | `0150`    | MyHealth pre-registration: `kiosk_registration.source` (`kiosk` or `myhealth`), `pre_registration_setting` (off by default)                                                               |

2. **Deploy order:** `migrate` first (it applies the migrations), then `api`, then the workers, then `staff` and `portal`, then the new **`kiosk`** app.
3. **The kiosk app is a new service** (`apps/kiosk`, its own `railway.json`, port from `PORT`), declared in `infrastructure/terraform/railway/` (`kiosk`; a public
   domain, `API_BASE_URL`, and `kiosk_privacy_notice` for `KIOSK_PRIVACY_NOTICE`). Run `terraform plan` and review the new service and domain before applying. Without
   Terraform, create the service by hand with `API_BASE_URL` (the API address including `/api/v1`) and optionally `KIOSK_PRIVACY_NOTICE` and `KIOSK_APP_VERSION`.
4. **The print agent** (`tools/kiosk-print-agent`) is not deployed with the platform; its printer is set in the staff app (**Queue → Devices → Edit → Printer**), so its
   environment holds only the API address and its sign-in (and a printer connected to its own computer, if any). `FACILITY_ID`, `DEVICE_CODES` and `PRINTER_*` are
   optional, and `PAPER_MM` is gone (the paper width is a setting). It is not deployed with the platform: it runs on a machine next to a printer, only for clinics that print
   tickets. It runs from the repository (`pnpm kiosk:print-agent`); a packaged install is not built. Follow `docs/runbooks/kiosk-print-agent.md`.
5. **Production configuration checks:** the API now refuses the placeholder JWT secret and the sample MFA key in production (security audit VR-21),
   and also the development LiveKit and object-storage credentials and a LiveKit secret shorter than 32 characters. Check all are real values before the
   first start.
6. **Zero-trust changes that stop a service from starting, or a feature from working, until done** (each is in the
   [zero-trust report](../security/zero-trust-audit-2026-11-06.md)):

   | Required before (or with) this release                                                                                                                                                                                               | Otherwise                                                                                                   |
   | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------- |

   | Configure ClamAV (`CLAMAV_HOST`), or set `MALWARE_SCAN_REQUIRED=false` to accept uploads as not scanned.                                                                                                                             | The API refuses to start in production.                                                                     |
   | Platform administrators turn on two-step verification (My account).                                                                                                                                                                  | Platform administrator routes answer `403 platform_admin_mfa_required`.                                     |
   | Move each instrument gateway to an account holding only the **Instrument gateway** role, give each instrument `allowedPeers` (the analyzer's IP addresses), and use an `https` API address.                                          | The gateway refuses to start, or refuses to send (broader account).                                         |
   | To remove archived audit months: the database owner sets `audit_retention_floor` (`docs/runbooks/audit-retention.md`).                                                                                                               | Nothing is removed (archiving still works).                                                                 |
   | Use TLS to PostgreSQL, Redis, SMTP and object storage, or set `ALLOW_PLAINTEXT_PRIVATE_NETWORK=true` for private-network hosts (Terraform does, for Railway's private network); LiveKit must be `wss://`.                            | The API and workers refuse to start in production.                                                          |

   | For video consultations: list the LiveKit address in `CSP_CONNECT_ORIGINS` on `staff` and `portal` (e.g. `wss://video.example.ph`).                                                                                                  | Their script policy blocks the video connection; the rest of the app works.                                 |

Nothing kiosk-related appears until an administrator ticks **Patient kiosk** on a visit type, creates a kiosk account and registers the device. **Prints
tickets** is off for every new kiosk.

## Changes you may notice

- **Government and insurance identifiers are masked** (last four digits) in the patient record and merge preview unless the person holds
  `patient.identifier.reveal`. Organization administrators, records officers, receptionists and cashiers keep seeing them in full; clinical roles see the masked form.
- **Managing users:** suspending, resetting or revoking a member needs every permission that member holds; a facility-scoped user manager can grant only at
  their own facilities and not to themselves.
- **Uploads:** the bytes of an uploaded file must match its declared type.
- **Rate limits:** kiosk, print agent and waiting-room screen routes are counted per signed-in device account; while Redis is unreachable the limiter counts
  in memory instead of letting everything through.
- **Web apps** send browser security headers, and the staff app, MyHealth and the kiosk a per-request script policy (pages render per request).
- The visit types screen has a **Patient kiosk** column, and the Devices screen a **Print agent** choice per kiosk.
- **Documents** in the patient's general list: dental images, outside results, laboratory reports, billing documents and copies of the record also need that
  area's permission (a nurse no longer sees dental images there); the records office still sees all. Management report files open only from Management.
- **Invoices, receipts and lab order cancellation** answer "not found" from another facility: switch to the invoice's or order's facility first.
- **Sign-in:** a locked account says "Invalid email or password" like a wrong password (the lock still lasts 15 minutes); a staff or MyHealth session not refreshed
  for 12 hours ends (`SESSION_IDLE_MINUTES`, `PORTAL_SESSION_IDLE_MINUTES`); a sign-in challenge and a live-update ticket work once.
- **Waiting-room screens** receive only that the queue changed; a suspended or signed-out user's live updates stop within a minute.
- **Offline page:** its copy is taken only when the page is opened, kept at most 12 hours and deleted at sign-out.
- **Web Push** works only with the browsers' own push services (Chrome, Edge, Firefox, Safari, Windows).
- **The MyHealth mobile app is its own project** (`myhealth-mobile`, history of `apps/mobile` carried over): `apps/mobile`, `pnpm mobile:apk`,
  `pnpm dev:mobile` and the committed `apps/portal/public/downloads/myhealth.apk` are gone from this repository (zero-trust finding F4: that APK was signed
  with the public template debug key). APKs are now built and signed by EAS with the organization's key in the new project, never committed; if a
  deployment set `MOBILE_APP_ANDROID_URL=/downloads/myhealth.apk`, point it at the new https link (or leave it unset) before deploying MyHealth, or the
  QR code leads to a missing file. The API side (`/api/v1/portal/*`, Expo push) is unchanged.

## Rollback

Migrations are forward-only. The new tables and columns are additive and older code ignores them, so redeploying the previous version works without undoing a
migration. Do not drop the new tables. See `docs/runbooks/releases.md`.

## Known gaps

- **Intermittent printing journey.** In two earlier full runs the first test of the printing journey failed because the print agent was still waiting out a refused
  sign-in when the test checked in a ticket (the API accepts about ten sign-ins a minute per address). The journey now waits for the agent to sign in; the next full run
  passed, which is not proof that it cannot recur.
- **Final journey run (2026-11-07).** In the full run, five journeys that store documents (13, 15, 23, 24, 25) failed only because object storage was not running on
  the test machine (connection refused to `localhost:9000`); with it running they all passed. The printing journey (28) failed twice more, each time with a
  connection reset and never on a check: once a kept-alive API connection closed under a request (the API now keeps idle connections 65 s, longer than clients
  and Railway's proxy reuse them, and the journey retries an idempotent `GET` once), once the stand-in printer's dropped connection had no error handler (the
  journey now ignores it). With both fixed, journey 28 passed (5 of 5).

- Kiosk audit finding **KA-10** (guidance, now in the manual) is closed as documentation; **KA-11** (browser journeys for the voice announcement, queue transfer and two counters at once, journey 33) is fixed;
  **KA-12** (hardware and ZAP checks not run) is open; the other findings are _fixed, pending verification_, not verified.
- **KA-16** (found by journey 33): when a waiting-room screen had shown no call yet and two calls arrived in one refresh, only the newest was read out. Calls made
  in the last 30 seconds are now all announced, oldest first; a screen reloading with old calls still reads only the newest.
- A print agent that crashes between printing and reporting can print one ticket twice; a very slow print could be repeated by a second agent; tickets are plain
  ASCII; the Devices page does not refresh by itself; the kiosk screen has no Filipino wording.
- Compliance items stay with the organization: the kiosk's privacy notice wording, how long kiosk sessions and print history are kept, what a kiosk may
  collect. See `docs/security/compliance-dependencies.md`.
